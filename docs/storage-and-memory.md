# 저장소 / 메모리 구조

## 대화 DB와 기존 데이터 이전

대화의 기본 저장소는 Android 내장 `SQLiteOpenHelper`로 관리하는 `conversations.db`입니다. Room 의존성을 추가하지 않습니다. 방, 참여자, 메시지, 가져오기 이력, 자동 말투 프로필과 이전 완료 표식을 관리하며, 가져오기·삭제·이전은 트랜잭션으로 처리합니다.

- 방은 표시 이름과 별개의 UUID로 식별합니다. 같은 이름의 방도 독립된 기록입니다.
- 메시지는 발화자·본문·원본 시각·수집 출처와 `SELF`, `OTHER`, `AI`, `UNKNOWN` 구분을 저장합니다.
- `auto_reply_configs/`의 응답 설정 JSON과 SharedPreferences의 수동 설정은 유지합니다.
- 기존 `room_state/` JSON은 DB 커밋 이후에만 삭제합니다. 이전 표식으로 재실행 중복을 막으며, 파싱 불가 파일은 성공한 것으로 처리하지 않습니다.
- 레거시 수신 발화는 `UNKNOWN`, 기존 앱 발신은 `AI`로 이전합니다. 이름 일치만으로 `SELF`로 승격하지 않습니다. 출처가 섞인 기존 자동 요약은 폐기하고 수동 설정은 보존합니다.

## 파일 가져오기와 본인 식별

Android 카카오톡 UTF-8 텍스트 내보내기를 우선 지원합니다. UI에서 최대 10 MiB를 읽으며, 파싱·DB 저장·분석은 UI 스레드 밖에서 실행합니다. 여러 줄 발화를 보존하고 잘못된 날짜·지원하지 않는 구간은 경고로 표시합니다. 전역 내 이름은 본인 식별 근거가 아닙니다. 파일의 참여자 목록에서 본인을 명시적으로 선택해야 합니다.

같은 방에서 원본 시각·발화자·본문과 동일 항목의 등장 순번을 사용해 재가져오기를 중복 제거합니다. 같은 문장을 같은 시각에 실제로 반복한 항목은 보존합니다. 파일을 서로 다른 방에 넣으면 별도 기록이므로 대상을 직접 확인해야 합니다. 기존 본인 선택과 다른 참여자를 선택한 가져오기는 거부합니다.

앱의 생성 기록과 본문·시각이 일치하는 발화는 방이 달라도 `AI`로 분류합니다. 이는 알려진 생성 기록에 대한 비교이며 모든 자동답장 탐지가 아닙니다. 수집 OFF 중 생성됐거나 이전·외부 봇이 만든 답장은 내보내기 파일만으로 확인할 수 없습니다. 사용자는 본인으로 선택한 참여자의 발화가 직접 작성한 내용인지 확인하고, 자동답장이 섞였으면 정리해야 합니다. 동명이인도 파일 정보만으로 구분할 수 없습니다. 레거시 CSV 호환 가져오기는 `UNKNOWN`으로만 보존하며 내 말투 학습 경로가 아닙니다.

## 알림 수집과 연결

새로 관측한 방은 메타데이터만 등록하고 본문 수집은 기본 OFF입니다. 알림 출처는 Android 사용자·패키지·shortcut ID를 사용하며, shortcut이 없으면 notification key로 구분합니다. 표시 이름만으로 합치지 않지만 알림 key의 재사용·변경 가능성은 실제 기기에서 검증해야 합니다.

사용자가 가져온 방과 관측된 알림 방을 직접 연결하면 **이후 알림만** 가져온 방으로 들어갑니다. 이전에 관측 방에 저장한 대화는 기존 ID에 남습니다. 연결 시 양쪽 수집은 OFF로 바뀌므로 원하는 방에서 다시 켜야 합니다. 알림 연결과 데이터 가져오기는 자동답장을 활성화하지 않습니다.

실제 저장은 DB의 방별 수집 동의와 기존 응답 설정의 수집 조건을 함께 통과해야 합니다. 자동답장 OFF는 수집 동의를 취소하지 않습니다. 수집 OFF인 방은 수신 본문과 생성 답장을 이 경로로 저장하지 않습니다. 상대방의 수신 알림은 `OTHER`이며, 직접 보낸 내 메시지를 알림만으로 지속 수집하지 않습니다.

## 말투 분석과 적용

모델 가중치를 재학습하지 않습니다. 최근 90일의 최대 500개 발화를 통계와 대표 예문으로 요약해 프롬프트에 적용합니다. 12개 미만인 프로필은 자동 적용을 보류합니다.

- 내 말투는 `SELF`만 분석합니다. 방 분위기는 `SELF`와 `OTHER`를 분석하며 `AI`와 `UNKNOWN`은 제외합니다.
- 존댓말 비율, 평균 길이, 종결 표현, 줄바꿈, 질문·웃음·감탄부호·이모지 비율을 계산합니다.
- 대표 예문은 연락처·URL·숫자를 일부 치환한 형식 참고 자료입니다. 모든 개인정보를 익명화한 자료는 아니며 예문의 내용을 현재 사실로 사용하지 않도록 프롬프트에 명시합니다.
- 수동 예문·수동 방 말투·수동 수정값이 우선합니다. 자동 값은 방별 내 말투를 먼저 쓰고, 부족하면 전체 내 말투를 참고하며 방 분위기는 별도로 제공합니다.
- 새로운 저장은 분석 갱신을 묶어 예약합니다. 변경된 프로필만 다시 계산하며 답장마다 전체 이력을 재분석하지 않습니다.
- 새 미리보기는 표본 수·분석 기간·갱신 시각을 표시합니다. 기존 설정 화면의 보조 라벨도 표본에 대한 안내이며 생성 답장의 정확도 점수가 아닙니다.

## 보관과 삭제

기본 보관·분석 범위는 최근 90일입니다. 가져올 때 기간 밖 발화와 미래 시각은 건너뜁니다. DB 초기화·접근과 실행 중 정기 유지보수에서 만료 원문·관련 참여자·가져오기 메타데이터를 정리하고 프로필을 남은 표본으로 재계산합니다. 백그라운드 정리는 기기와 Android 작업 스케줄링 상태에 따라 지연될 수 있으므로 정확히 90일 시점의 즉시 삭제를 보장하지 않습니다.

`학습 데이터 삭제`는 해당 방의 원문·참여자·가져오기 이력·본인 선택·대표 예문·자동 프로필 기여분과 자동 메모리를 정리합니다. 전체 내 말투도 남은 다른 방의 표본으로 다시 계산합니다. 해당 표본을 이미 참고한 다른 방의 생성 작업도 전송 전에 폐기합니다. 저장 시 원문을 남겼던 이전 로그의 잔존 가능성 때문에 삭제 시 최근 운영 로그도 함께 비웁니다. 수동 예문·수동 방 말투·응답 대상 설정은 유지합니다. 수집이 켜져 있으면 이후 새 메시지는 다시 쌓입니다. 데이터 삭제는 수집 중지와 별개입니다.

실행 중에는 1시간 간격, Android JobScheduler에는 하루 주기로 유지보수를 예약합니다. 앱 재시작과 DB 접근에서도 만료 자료를 확인합니다. 강제 종료·재부팅 후 앱을 다시 열기 전이나 OS 지연 상황에서는 백그라운드 작업이 실행되지 않을 수 있습니다.

DB는 외래 키를 활성화하고 `secure_delete`를 사용합니다. 이 설정은 기기 저장장치 전체의 물리적 삭제를 보장하지 않습니다. 앱 데이터는 Manifest와 백업 XML에서 클라우드 백업 및 기기 이전 대상에서 제외합니다.

## 운영 로그와 통계

신규 로그는 메시지 본문을 기록하지 않는 운영 정보 중심입니다. 로그 복사 마스킹은 레거시 로그와 비정형 문자열에 대한 방어로 유지합니다. 원본 복사 전 경고도 유지하며 외부 전송은 하지 않습니다. 로컬 로그는 최근 100줄, 파일 갱신 시각 기준 7일로 제한하고 다음 읽기·쓰기에 정리합니다.

`ReplyStatsPrefs`는 수신·전송 요청·스킵·실패와 원인별 집계를 저장합니다. `ReplyCandidateStatsPrefs`는 후보 source별 생성·선택·빈 응답·품질 미달 횟수와 latency를 저장하며 프롬프트·원문 응답을 저장하지 않습니다. `SendResult(sent, reason)`은 전송 요청 처리 결과입니다. 실제 카카오톡 도착 여부는 별도 확인해야 합니다.
