# 카카오톡 방 직접 선택과 공식 API 조건

확인일: 2026-09-12. 현재 구현은 사용자가 카카오톡 대화방에서 `현재 방 선택` 버튼을 직접 누를 때 상단의 방 이름을 읽는 Android 접근성 방식입니다. 카카오 공식 채팅방 API를 호출하거나 전체 방 목록을 가져오는 기능은 아닙니다.

## 직접 선택의 범위

사용자는 시스템 설정에서 `카카오톡 방 직접 선택` 접근성 서비스를 직접 켜고, 앱의 선택 버튼으로 2분 세션을 시작합니다. 카카오톡에서 원하는 대화방을 연 뒤 화면 위의 `현재 방 선택` 버튼을 누릅니다. 이미 열린 대화방도 같은 버튼으로 선택합니다. 앱으로 돌아와 표시된 이름을 명시적으로 확인해야 등록하며, 취소·만료·서비스 종료·프로세스 종료 후에는 이전 결과를 사용할 수 없습니다. 자동 복귀가 되지 않으면 최근 앱에서 직접 돌아와 확인할 수 있습니다. 기존 알림이나 대화 파일은 선택의 전제 조건이 아닙니다.

서비스는 활성 세션에서 카카오톡 위에 접근성 오버레이 버튼을 표시합니다. 사용자가 `현재 방 선택`을 누를 때만 현재 카카오톡 대화방의 알려진 툴바 제목을 조회합니다. 방 목록의 클릭 이벤트에서 제목을 추정하지 않습니다. 메시지 본문·미리보기·이벤트 텍스트는 읽거나 기록하지 않으며 자동 탭·스와이프도 수행하지 않습니다. 제목을 하나로 확인할 수 없으면 좌표·이전 화면 캐시로 추측하지 않습니다.

확인된 제목 노드의 `text`가 비어 있으면 같은 노드의 `contentDescription`만 확인합니다. 카카오톡의 확인된 제목 뷰는 `text`가 비어 있고 접근성 설명에 값을 제공했습니다. 두 필드는 별도 값이므로 설명을 사용한 경우에도 앱에서 실제 방 이름과 일치하는지 사용자가 확인해야 합니다. 다른 노드의 설명을 검색하거나 읽지 않으며, 빈 값과 512자 초과 값은 각각 실패로 처리합니다. 길이가 초과된 텍스트를 자르거나 설명으로 대체하지 않습니다. [AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo)

Android는 접근성 서비스의 UI 트리 조회와 리소스 ID 보고를 각각 명시적으로 설정하도록 합니다. 사용자가 버튼을 누른 시점에 제목을 확인할 수 없거나 카카오톡 UI가 바뀌면 재선택이 필요할 수 있습니다. 이는 공식 Kakao API의 호환성 계약이 아닙니다. [Android 접근성 서비스 설정](https://developer.android.com/guide/topics/ui/accessibility/service), [AccessibilityNodeInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo)

선택 결과는 **방 이름뿐**입니다. 앱이 만드는 UUID는 로컬 기록 ID이며 카카오톡 고유 채팅방 ID가 아닙니다. 같은 이름의 실제 방은 구분할 수 없고 이후 이름이 같은 수신 알림이 같은 선택 규칙에 들어올 수 있습니다. 방 이름을 서로 다르게 설정한 뒤 사용해야 하며 이름 변경 후에는 선택·응답 조건을 다시 확인해야 합니다.

방 선택과 메시지 수집은 별도입니다. 선택에는 알림이 필요 없지만 이후 수신 메시지 수집에는 알림 접근 권한과 방별 수집 확인이 필요합니다. 직접 선택은 과거 대화나 직접 보낸 메시지를 읽지 않습니다. 해당 자료의 분석에는 별도 `과거 대화 파일 가져오기`를 사용합니다. 수집 시작만으로 AI 자동답장을 켜지 않습니다.

## 창 조회와 실패 진단

버튼을 누르면 오버레이를 제거하고 150ms 뒤 현재 활성 앱 창을 한 번 조회합니다. 활성 앱 창이 없으면 입력 포커스 앱 창을 확인하며 후보가 정확히 하나이고 카카오톡일 때만 제목 검사를 진행합니다. 뒤에 열린 카카오톡 창을 대신 선택하지 않습니다. `FLAG_RETRIEVE_INTERACTIVE_WINDOWS`로 실제 앱 창을 구분하고 제목·채팅 목록·입력창의 누락, 숨김, 중복을 각각 안내합니다. Debug 빌드의 `RoomSelection` 로그에는 고정된 실패 코드만 남기며 제목·본문·예외 메시지는 기록하지 않습니다.

UiAutomation은 일반 접근성 서비스와 노출 범위가 다를 수 있고 기본적으로 다른 서비스를 억제할 수 있습니다. 따라서 UI 덤프에서 제목 ID가 보이는 것만으로 실기기 선택 성공을 주장하지 않습니다. 활성 선택 도중 UI 덤프를 실행하지 않고 실제 서비스의 결과와 사용자 확인으로 검증합니다. [UiAutomation](https://developer.android.com/reference/android/app/UiAutomation)

## 공개 API와 Partner API

| 경로 | 확인한 범위 | 이 앱에서의 판단 |
| --- | --- | --- |
| 공개 카카오톡 소셜 | 공개 문서는 프로필·친구 목록·친구 피커를 설명합니다. 일반 사용자의 전체 채팅방 목록 조회는 공개 기능 목록에서 확인되지 않습니다. | 일반 공개 SDK 추가만으로 방 목록을 얻는다고 가정하지 않습니다. |
| Partner 카카오 소셜 | 공식 검색 색인에는 채팅방 피커와 공동체 앱 권한·추가 신청 조건이 안내됩니다. | 해당 앱의 공동체/Partner 자격과 실제 승인 권한은 미확인입니다. 현재 사용 가능하다고 표시하거나 호출하지 않습니다. |
| 공개 카카오톡 공유 | 친구·채팅방을 대상으로 콘텐츠 메시지를 보내는 공유 흐름입니다. | 메시지 전송 없는 중립적인 방 선택의 대체 기능으로 사용하지 않습니다. |

공개 범위 판단은 [카카오톡 소셜 이해하기](https://developers.kakao.com/docs/ko/kakaotalk-social/common)의 제공 기능을 기준으로 합니다. 이것은 모든 계약형 API의 부재를 뜻하지 않습니다.

Partner 조건은 [카카오 소셜 이해하기](https://developers.kakao.com/docs/in/kakao-social/common), [Partner Android](https://developers.kakao.com/docs/in/kakao-social/android), [JavaScript](https://developers.kakao.com/docs/in/kakao-social/js)의 공식 검색 색인으로 확인했습니다. 직접 문서 열기는 로그인 화면으로 이동하여 인증 후 전체 내용은 확인하지 못했습니다. 검색 색인에 문서가 보이는 것과 해당 개발자 앱에 권한이 부여된 것은 다릅니다. 현재 계정·앱의 자격, 필요한 동의항목·승인 범위·요금 적용 여부를 관리 콘솔과 카카오 담당 채널에서 확인한 뒤에만 공식 피커 도입을 검토할 수 있습니다. 이 저장소에는 Partner SDK나 비공개 문서의 구현 예제를 추가하지 않습니다.

[카카오톡 공유 이해하기](https://developers.kakao.com/docs/ko/kakaotalk-share/common)는 공유 대상 선택과 메시지 발송을 하나의 사용자 흐름으로 설명합니다. 빈 메시지나 시험 메시지를 보내서 방 선택 결과를 얻는 방식은 이 기능의 목적에 포함하지 않습니다.

## 검증과 남은 조건

세션 만료·취소·중복 선택은 JVM 테스트로 확인합니다. 접근성 권한은 자동으로 켜지 않으며 사용자가 시스템 설정에서 직접 허용해야 합니다. 실제 카카오톡에서 오버레이 표시, 현재 방 제목 추출, 확인 화면 복귀는 해당 카카오톡 버전의 실기기 테스트가 필요합니다. 에뮬레이터의 앱 내부 UI 테스트나 파일 가져오기 성공을 직접 선택 성공으로 대체하지 않습니다.
