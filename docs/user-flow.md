# 사용자 플로우

## 대화로 말투 준비하기

1. 메인 화면의 `대화 수집·말투 분석`을 엽니다. 방 선택은 아래의 직접 선택 흐름을 사용하며, 과거 말투 분석에만 파일 가져오기가 필요합니다. 새 방의 본문 수집은 기본 OFF입니다.
2. 선택 사항인 `과거 대화 파일 가져오기`에서 Android 카카오톡 UTF-8 `.txt` 내보내기를 선택합니다. 10 MiB를 넘거나 파싱할 수 없는 파일은 오류를 표시합니다.
3. 감지된 참여자 중 본인을 선택하고 새 방 또는 기존 저장 방을 직접 선택합니다. 방 이름과 짧은 ID를 함께 표시하며 이름만으로 자동 병합하지 않습니다.
4. 메시지 수·해석 경고·최근 90일 보관 조건을 검토합니다. 동명이인이나 이전·외부 자동답장이 포함된 파일은 정리 후 가져와야 합니다. 본인 선택은 그 이름의 발화가 직접 작성한 내용이라는 확인을 전제로 합니다.
5. 저장 결과에서 추가·중복·보관 기간 밖 개수를 확인합니다. 가져오기는 자동답장을 켜지 않습니다.
6. `이 방의 내 말투`, `전체 내 말투`, `방의 대화 분위기`의 표본 수·분석 기간·갱신 시각을 봅니다. 분석 가능한 표본 12개부터 적용합니다.

파일을 다시 가져오면 같은 방의 중복 메시지는 건너뜁니다. 내보내기에 동명이인을 구분할 정보가 없으면 본인 발화를 정확히 분리할 수 없습니다. 앱이 생성 기록으로 확인한 AI 답장은 제외하지만 외부·이전 자동답장을 모두 탐지하지는 못합니다.

## 이후 알림 누적하기

파일에서 가져온 방을 기존 알림 기록과 연결하려면 알림에서 실제 방을 관측한 뒤 `알림 방 연결`에서 대상 방을 직접 확인합니다. 연결은 이후 알림만 바꾸며 기존 관측 방의 기록은 별도로 남습니다. 연결 직후 수집은 OFF이므로 `이 방의 알림 수집`을 켭니다. 이 연결 기능은 아래의 카카오톡 직접 선택과 별개이며, 표시 이름만으로 올바른 방이라고 판단하지 않습니다.

알림 수집은 상대방의 수신 발화를 쌓아 방 분위기를 갱신합니다. 사용자가 직접 보낸 메시지를 계속 확보하는 기능은 아니므로 본인 말투 최신화에는 파일 재가져오기가 필요합니다. 분석은 백그라운드에서 묶어 갱신하며 파일 읽기·DB 처리 중에는 중복 동작을 막습니다.

## 답장 설정과 수동 조정

`AI 답장 설정`에서 로컬 모델을 준비하고 `대상 방 관리`에서 응답할 방·발화자 조건·트리거를 정한 뒤 전역 자동답장을 켭니다. 에뮬레이터에서는 Gemma/LiteRT-LM 모델 생성 검증을 완료할 수 없으며 ARM64 실기기가 필요합니다.

직접 입력하는 페르소나·예문·방 메모리·수동 방 말투는 선택 사항입니다. 수동 수정은 자동 분석보다 우선합니다. 자동 분석은 방별 내 말투, 표본이 부족할 때 전체 내 말투를 참고하고 방 분위기를 별도로 반영합니다. 대표 예문은 표현 형식만 참고하며 날짜·장소 등 현재 사실의 근거로 사용하지 않습니다.

응답 설정 화면은 현재 메시지·최근 대화·직접 입력한 방 메모를 사실 근거로, 수동 예시·자동 말투를 표현 참고로 안내합니다. 기존 학습 말투 설정에서 사용 여부와 수동 수정값을 조정할 수 있습니다. 수동 수정값이 없는 새 방은 초기화 버튼이 비활성화된 `수정 없음` 상태입니다. `수정 초기화`는 수동 override만 지웁니다. 잘못된 원문까지 없애려면 `학습 데이터 삭제`를 사용합니다. 새 미리보기의 표본 정보와 기존 보조 라벨은 모델 답장의 정확도를 뜻하지 않습니다.

답장은 방·발화자·트리거 조건과 후보 품질 평가를 통과하면 자동 전송합니다. 생성 후보가 모두 약하면 보류할 수 있으며 전송 요청 성공과 실제 카카오톡 대화창 표시 여부는 구분해 확인합니다.

## 보관·삭제와 운영

- 자동답장 OFF는 답장만 중단합니다. 수집 동의를 켠 방의 저장은 계속됩니다.
- 수집 OFF는 이후 본문 저장을 중단합니다. 이미 저장된 기록은 삭제 기능으로 지웁니다.
- `학습 데이터 삭제`는 해당 방의 원문·대표 예문·자동 분석·본인 선택을 정리하고 전체 내 말투를 재계산합니다. 수동 설정은 유지하며 수집이 켜져 있으면 새 메시지가 다시 쌓입니다.
- 최근 90일을 보관합니다. 앱 실행·DB 접근·예약 작업 시 정리하므로 앱이 장기간 중지되면 다음 실행까지 삭제가 지연될 수 있습니다.
- 대화와 설정은 클라우드 백업·기기 이전 대상에서 제외됩니다.
- 메인 화면에서는 응답 통계·실패 원인, 로그 복사·삭제, 테마를 관리합니다. 신규 운영 로그에는 메시지 본문을 넣지 않으며 기존 로그를 고려해 복사 마스킹과 원본 복사 경고를 유지합니다.
## 문구와 접근성

화면 문구와 설정 설명은 문자열 리소스를 공용으로 사용합니다. UI 검사는 설명 전문 대신 안정적인 ID를 사용합니다. 로그는 표준 NestedScrollView로 탐색하고 채팅 시각은 12sp로 표시합니다. 장식 아이콘은 접근성 탐색에서 제외합니다. 방 목록은 메모·활성 상태를 비교해 변경된 행을 갱신합니다.

## 카카오톡 방 선택

대상 방 관리에서 직접 선택을 시작하면 안내 화면이 열립니다.

1. 처음에는 시스템 설정에서 `카카오톡 방 직접 선택` 접근성 서비스를 직접 켭니다.
2. 앱에서 `선택 시작 · 카카오톡 열기`를 누르고 원하는 대화방을 엽니다. 이미 열린 대화방도 선택할 수 있습니다.
3. 시작한 뒤 2분 안에 카카오톡 위에 표시되는 `현재 방 선택` 버튼을 누릅니다. 방을 열거나 제목을 누르는 동작만으로는 선택하지 않습니다.
4. 앱으로 돌아와 표시된 이름을 확인하고 `이 방 선택 확인`을 누릅니다. 자동으로 돌아오지 않으면 최근 앱에서 직접 돌아옵니다.

취소·시간 초과·서비스 종료 시 선택 결과는 폐기합니다. 버튼이 보이지 않거나 선택 시간이 지났으면 앱으로 돌아와 다시 시작합니다.

선택 단계는 알림 목록이나 파일 관리자를 사용하지 않습니다. 접근성 서비스는 유효한 선택 세션에서 `현재 방 선택`을 직접 누를 때만 현재 대화방 상단의 제목을 읽습니다. 메시지 본문·미리보기를 수집하지 않으며 화면을 자동으로 누르지 않습니다. 제목을 하나로 확인할 수 없으면 추측하지 않고 재선택을 요구합니다. 화면 이름만 얻으므로 동명 방을 구분할 수 없으며 로컬 ID를 카카오톡 고유 ID로 표시하지 않습니다. 카카오톡 업데이트로 화면 구조가 달라지면 선택이 실패할 수 있습니다.

대화 수집 화면도 직접 선택 흐름을 제공합니다. 방 이름을 확인한 뒤 `수집 시작`을 확인하면 이후 수신 알림 수집만 켜고 AI 답장은 켜지 않습니다. 실제 수집에는 별도로 알림 접근 허용과 새 수신 알림이 필요합니다. 과거 대화 파일 가져오기는 목록 아래의 별도 보조 기능이며 파일 관리자는 이 버튼에서만 열립니다. 과거 대화와 직접 보낸 메시지를 자동으로 읽지는 않습니다. 공식 API와 접근성 방식의 차이는 [카카오톡 방 선택](kakao-room-selection.md)을 참고합니다.
